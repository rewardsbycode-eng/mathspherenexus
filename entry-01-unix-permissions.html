MN-Dev Guide — the Universal Workshop

Entry No. 1 — Unix Permissions: The Complete Number Guide

Knowledge from the workshop, for every developer.

This entry explains every Unix permission number from the lowest (000) to the highest (777): what each digit means, what each common number allows, the exact commands to inspect and set them, and the recommended practice for private, shared, and public files. Everything here applies to any Linux or macOS system.

1. The one idea underneath all of it

Every file and every folder carries permissions for THREE audiences, in a fixed order:

  1. Owner — the one account that owns it.
  2. Group — the accounts in its group.
  3. Others — every other account on the machine.

For each audience, three actions can be allowed or denied:

  • Read — see what is inside.
  • Write — change it.
  • Execute — on a file: run it as a program. On a folder: ENTER it and reach what is inside.

A permission number is three digits — one digit per audience, in that order: OWNER, GROUP, OTHERS. Example: 750 means owner 7, group 5, others 0.

2. The eight digits (0–7) — the whole system

Each digit is a sum. Read = 4, Write = 2, Execute = 1. Add the actions you want to allow; the total is the digit.

Digit Letters Allows
0 --- Nothing at all
1 --x Execute / enter only
2 -w- Write only (rare alone)
3 -wx Write + execute, no read
4 r-- Read only
5 r-x Read + execute, no changes
6 rw- Read + write, no execute
7 rwx Everything: read, write, execute

That table is complete. Every permission number ever used — all 512 combinations from 000 to 777 — is just three of these digits side by side. Read any number digit by digit and you know exactly what it allows, for whom.

One digit deserves a warning: write without read (2) cannot show you a file's contents, but it can still open the file to overwrite it or append to it — a write-only file can be clobbered blind. Rare alone, but never mistake it for protection.

3. Reading what a machine shows you

  • ls -l shows letters: rwxr-xr-x is 755 — owner rwx (7), group r-x (5), others r-x (5). The very first character is the type: d for a directory, - for a file.
  • stat -c '%a %n' <path> shows the number itself (on macOS: stat -f '%Lp %N' <path>).

4. Files and folders obey the same digits differently

The digits are the same; what the actions DO depends on the kind of thing:

  • On a file: read = open and read it; write = change or erase its contents; execute = run it as a program or script.
  • On a folder: read = list the names inside; write = create, delete, or rename things inside; execute = enter it and reach the things inside.

Two consequences worth knowing:

  • A folder at 700 with a file at 600 inside is a locked room with a locked drawer: nobody else can even enter the room.
  • A file's own number cannot protect it if the FOLDER is open: write permission on a folder is what allows deleting the files inside it, even files set to 600. Folders matter as much as files — set both.
  • Read on a folder without execute is a half-power: you can list the names inside, but you cannot open, inspect, or use anything in it — names without reach. Listing is not access.

5. The ladder — lowest to highest

The numbers that actually occur, in order, with what each one means in practice. (Any number not listed is read straight off the digit table in section 2.)

Number Who can do what Where it belongs
000 Nobody, not even the owner, can read, write, or enter A deliberate lockout; the owner can still change the number back
400 Owner reads; nobody writes; nobody else anything A finished file frozen against changes
444 Everyone reads; nobody writes Public read-only
600 Owner reads and writes; group and others NOTHING Private files
640 Owner reads/writes; group reads; others nothing Shared with one trusted group
644 Owner reads/writes; everyone else reads Ordinary public files (web pages, documents)
660 Owner and group read/write; others nothing Group working files
664 Owner and group read/write; others read The default new-file number under umask 002
700 Owner does everything; group and others NOTHING Private folders
750 Owner everything; group read + enter; others nothing A folder one group may look into
755 Owner everything; everyone else read + enter Ordinary public folders and programs
770 Owner and group everything; others nothing A group's private working folder
775 Owner and group everything; others read + enter The default new-folder number under umask 002
777 Everyone can do everything No privacy at all; avoid on anything that matters

6. The fourth digit (a short note)

Some numbers carry a leading fourth digit for special flags: 4 = setuid (run as the owner), 2 = setgid (run as the group; on a folder, new files inherit its group), 1 = sticky (on a shared folder, only a file's owner may delete it — the 1777 of a public temp folder). Everyday work almost never needs them. They are named here so a four-digit number is never a mystery: read the last three digits by the normal rules.

7. Where a new file's number comes from (umask)

New folders start from 777 and new files from 666, and the shell's umask subtracts. A common umask is 002, so new folders arrive at 775 and new files at 664; under umask 022 they arrive at 755 and 644. A number a file is born with is not a decision — check what you actually have (section 8) and set what you intend.

8. Doing it — the commands, step by step

Inspect one file or folder:

stat -c '%a %U:%G %n' path/to/thing

Inspect a whole tree (every folder and file, with its number and owner):

find path/to/tree -type d -exec stat -c '%a %U:%G %n' {} + | sort -k3
  find path/to/tree -type f -exec stat -c '%a %U:%G %n' {} + | sort -k3

Summarize a tree — how many items carry each number:

find path/to/tree -type d -printf '%m\n' | sort | uniq -c | sort -rn
  find path/to/tree -type f -printf '%m\n' | sort | uniq -c | sort -rn

Set a number:

chmod 700 path/to/folder
  chmod 600 path/to/file

The same settings in words (u = owner, g = group, o = others):

chmod u=rwx,go= path/to/folder
  chmod u=rw,go= path/to/file

Make a whole private tree owner-only — folders to 700, files to 600 — then verify:

find path/to/tree -type d -exec chmod 700 {} +
  find path/to/tree -type f -exec chmod 600 {} +
  find path/to/tree \( -type d ! -perm 700 -o -type f ! -perm 600 \) -print

The last command must print NOTHING: anything it lists is an item that did not take the intended number. Run the inspection again after any change — a change you have not re-read is a change you have not confirmed.

9. Recommended practice

  • Private storage (backups, archives, personal data, keys, anything not meant to be shared): folders 700, files 600. This is the most conservative practical posture — stricter either locks the owner out of working files or breaks the writes that backups and updates need.
  • Shared with a trusted group: folders 770 or 750, files 660 or 640, depending on whether the group writes or only reads.
  • Deliberately public (a web root, published documents): files 644, folders 755 — chosen on purpose, never arrived at by default.
  • Never 777 on anything that matters: it gives every account on the machine full control, including deleting the contents.

The boundary, stated once and plainly: permissions control OTHER ACCOUNTS on the same machine. They do not protect a drive that is plugged into another machine, and they do not stop the owner account itself — only encryption protects data at rest against physical access. Use permissions for access control; use encryption for theft and loss. A complete setup uses both, each for what it actually does.

10. Worked examples

  • A backups folder found at 755 — every account could enter and read it. Tightened: folder to 700, the backup files inside to 600, verified by re-inspection. Same backups, same owner — nobody else can open them now.
  • A private notes file created at 664 — the umask default, readable by everyone. Set to 600: owner-only, and it stays editable by its owner.
  • A shared project folder at 770 with files at 660 — the whole team reads and writes, other accounts get nothing. Correct as designed; no change.
  • A web root at 755 with pages at 644 — public on purpose, so the site can be served. Correct as designed; public is a choice, not a default that happened to you.
