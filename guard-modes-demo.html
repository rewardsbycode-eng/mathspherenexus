Guard Modes, Demonstrated

November 17, 2026 — by Alexander Sanchez

Guard modes bind: they are the server code of the Wizard Central Pro AI Modes Toolkit that checks a model’s call before it runs, and refuses it when the call breaks the person’s rules. This page is the record of the nine built guard modes exercised live, in one demonstration run, through the bridge’s real serve path — every scenario, every refusal, and the verdict.

The run

MachineMSI Gaming Trident 3 (Ubuntu 26.04.1)

ResultPASS — 18 of 18 scenarios behaved as expected, exit 0

The demo runs against a scratch HOME created for the demo, so the person’s real settings, grants and receipts are never touched. The demo’s own receipts are kept in the scratch folder and can be inspected afterwards.

What this demo is: the nine built guard modes, exercised live through the bridge’s real serve path (plus two check-level scenarios, labeled as such, where no shipped tool exercises the check end-to-end), and the five advisory twins’ verifier exercised on the composition path. What it is not: the fourteen pending guard modes are listed, not run — they are not built, and this demo does not pretend otherwise.

Part 1 — The bridge: guard modes bind, before the call runs

Demo tools: bannerwiz__mural (declares no paths) and jsonwiz__stats (declares paths).

S1 — Clean call

A well-formed call passes all nine guards and completes.

S2 — boundaryguard: an absolute path to a tool that declares none

refused by a guard mode: the tool bannerwiz:mural declares no paths, but an argument looks like an absolute path (/etc/passwd) - send only the arguments the tool declares, or ask a person to grant the folder

S3 — envelopeguard: shape of the arguments

End-to-end, a control character in an argument is refused:

refused by a guard mode: an argument holds control characters - send plain text only

At the check level (the manifest parser stops these shapes before the guard’s own check on the serve path):

  • 41 arguments → “too many arguments (41; at most 40) - send fewer, or split the work into several calls”
  • 4097 characters → “an argument is over 4096 characters (4097) - send a path to the file instead of its contents”
  • a non-text argument → “an argument is not text - every argument must be a string”

S4 — secretguard: an argument shaped like an API key

refused by a guard mode: an argument to bannerwiz:mural contains an Anthropic API key - secrets never travel through the bridge; remove it, refer to the secret by name instead, or have the person make the call at a terminal

The fake key used in the scenario appears nowhere in the refusal — the refusal names the kind of secret, never its value.

S5 — offlineguard: an argument naming a network address

refused by a guard mode: an argument to bannerwiz:mural names a network address - this toolkit works locally; do the work without reaching the network

S6 — provenanceguard: a prompt with no origin

refused by a guard mode: a prompt with no query and no handles has no origin to compose from - send a query, or handles naming the modes to compose

S7 — calibrationguard: a human_only command (check level)

Shown at the check level on purpose: on the serve path, the human_only wall refuses the call before calibrationguard’s own check is reached.

  • writewiz:commit → “writewiz:commit is human_only - a person must run it at a terminal; ask them to”
  • jsonwiz:stats → passes

S8 — sizeguard: a granted file over the 10 MB limit

refused by a guard mode: …/demo-data/big.txt is 11534336 bytes, over the 10485760 byte limit - work on part of the file, split it, or ask the person to look at it

S9 — binaryguard: a binary file handed to a text tool (check level)

Shown at the check level, with the reason stated in the open: no shipped tool pairs a text class with declared paths, so no serve-path call can reach this check today.

  • text tool + binary file → “…/demo-data/bin.dat is a binary file - this tool works on text only; use a tool that handles binary, or ask the person to look at it”
  • files-class tool + the same file → passes (binary is its legitimate use)
  • text tool + a real text file → passes

S10 — selfauditguard: damaged grant state refuses the serve

With a deliberately damaged grant file planted in the scratch state:

refused by a guard mode: the grant state is damaged: gbad00000.json: ~/.mcp-wizard/grants/gbad00000.json is not valid JSON - a person must run mcpwiz grants and repair or revoke the named file

After the damaged file is removed, the same clean call completes again.

S11 — The off-switch

Guard modes are a person’s setting, honored by the bridge: with boundaryguard switched off, the S2 call is not refused by it; switched back on, it is refused again.

S12 — The fourteen pending guard modes, listed honestly

budgetguard, consentguard, fanoutguard, instructionguard, intactguard, lookfirstguard, manifestguard, overwriteguard, paceguard, persistenceguard, previewguard, redactguard, shellguard, traversalguard — no check function exists yet for any of them; the server lists them for display only. (Their designs were ruled on November 17, 2026; decided is not built.)

Receipts

The demo’s own refusals were written into its scratch receipts chain: 16 receipts, 7 of them refusals; hash-chain check: OK — verified with the bridge’s real receipt machinery, not by reading the file.

Part 2 — Composition: the five advisory twins, on the output

The same five concepts exist on the advisory side as AI modes with a verifier, verify_boundary(), which checks model output against a capability envelope. The twins kept their original names — the November 16, 2026 naming migration renamed the server guard modes only.

P1 — @boundarywiz: output claiming a forbidden tool

Output claiming writewiz (forbidden by the envelope) is caught — violations: ['used forbidden: writewiz']. An honest output passes.

P2 — @envelopewiz: no envelope

Composed without an envelope, any output passes the verifier — only the asking remains. The prompt advises; without an envelope there is nothing to verify against.

P3 — @provenancewiz: unsourced prose under strict provenance

An unsourced factual line is caught — violations: ["unsourced claim: 'The toolkit stores every receipt in a hash chained log insid'"]. The same line with a [source: …] marker passes.

P4 — @calibrationwiz: confidence above the calibration set

Claiming 0.90 confidence on a claim the calibration set scores at 0.15 is caught — violations: ["overconfident: 'the capital of Australia is Sydney' (said 0.90, known 0.15)"]. Calibrated confidence passes.

P5 — @selfauditwiz: a missing self-audit line

Output missing its required self-audit line is caught — violations: ['missing self-audit line']. Ending with self-audit: PASS verifies.

Provenance of this record

Written from the terminal output of the run itself. One earlier attempt is part of the record: script v1 stopped at S11 — it carried pre-migration guard-mode names (set_guard_mode("boundarywiz", …)) and the renamed contract refused the old spelling. S1–S10 had already passed in that attempt. v2 corrected the names in Part 1 only (Part 2’s twin names were never renamed) and the full run above is v2’s.
